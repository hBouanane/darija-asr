# darija-asr

Build a cleaner Moroccan Darija ASR dataset from [atlasia/MoulSot-Full](https://huggingface.co/datasets/atlasia/MoulSot-Full):
transcribe clips with several ASR models, let an LLM judge reconcile the transcripts,
measure everything against a human-checked gold set, and export training data.

```
prepare ─► transcribe (cohere, voxtral, moulsot) ─► agree ─► merge (LLM) ─► labels ─► build-train
                                                                              │
gold run ─► gold-export ─► hand-correct gold.csv ─────────────────────────► eval
```

## Sources

| source | what | notes |
|---|---|---|
| `reference` | MoulSot `text` column | Generated by Gemini 2.5 Pro, not human. Only in `100-gt-2.5`. |
| `cohere` | [CohereLabs/cohere-transcribe-arabic-07-2026](https://huggingface.co/CohereLabs/cohere-transcribe-arabic-07-2026) | Gated: accept the terms on the Hub. |
| `voxtral` | [mistralai/Voxtral-Mini-4B-Realtime-Arabic](https://huggingface.co/mistralai/Voxtral-Mini-4B-Realtime-Arabic) | 4.4B; on a T4 it runs in fp16 (no bf16). Check the smoke test. |
| `moulsot` | [atlasia/moulsot.v0.3](https://huggingface.co/atlasia/moulsot.v0.3) | Optional third voter. Trained on `100-gt-2.5`, so only use it on other splits. |

## Runs

Each YAML in `configs/` is a run: which clips, which sources, which thresholds.
Outputs go to `work/<run_name>/` and, if `hub_repo` is set, to a private HF dataset
repo so nothing is lost when Colab disconnects.

| config | clips | purpose |
|---|---|---|
| `gold.yaml` | 400 from `100-gt-2.5` **test** | Hand-corrected gold set. Never trained on. |
| `calib.yaml` | 5,000 from `100-gt-2.5` train | Iteration 1: 3 sources, tune thresholds and prompt. |
| `extra_v1.yaml` | 30,000 from `extra-gt-2.5` | Iteration 2: new clips, ASR models only. |

`extra-lt-2.5` (perceptual quality score PESQ < 2.5, i.e. noisy audio) is not used yet.

## Setup (Colab terminal)

```bash
pip install uv
git clone https://github.com/hBouanane/darija-asr.git && cd darija-asr
uv sync --extra asr          # Cohere + Voxtral
# uv sync --extra moulsot    # MoulSot.0.3 instead; it needs an older transformers, so the extras conflict.
#                            # Then run it with `uv run --extra moulsot darija ...`: a plain `uv run`
#                            # re-syncs huggingface-hub to the default (newer) version and breaks it.
# uv sync                    # no GPU stages: agree, merge, labels, eval
export HF_TOKEN=...          # write access: gated Cohere model + hub_repo
export ANTHROPIC_API_KEY=... # only for `merge`
```

Set `hub_repo` in `configs/base.yaml` (e.g. `your-username/darija-asr-work`).
Run every command below as `uv run darija ...` (or `uv run python -m darija_asr ...`) from the repo root.

## Workflow

```bash
# 0. Pilot: 30 clips, check each model's output, speed, and the judge, before anything big
P="-c configs/gold.yaml --set run_name=pilot --set select.n=30"
darija prepare    $P
darija smoke      $P --model cohere -n 10    # read the output next to the reference
darija smoke      $P --model voxtral -n 10   # fp16 on a T4, batched by 8: check it isn't garbage
darija smoke      $P --model voxtral -n 10 --set asr.models.voxtral.batch_size=1   # same clips unbatched: should match
darija transcribe $P --model cohere
darija transcribe $P --model voxtral
darija agree      $P --set agreement.sources=[reference,cohere,voxtral]
darija merge      $P --set agreement.sources=[reference,cohere,voxtral]
#    -> read work/pilot/merge/*.parquet next to the candidates; note the token totals it prints

# Before choosing selection settings for a split:
darija stats -c configs/extra_v1.yaml        # clips/channel, pesq, duration histogram

# 1. Gold set: sample, transcribe with every model, judge everything, export for correction
darija prepare     -c configs/gold.yaml
darija smoke       -c configs/gold.yaml --model cohere      # sanity-check output + speed first
darija transcribe  -c configs/gold.yaml --model cohere
darija transcribe  -c configs/gold.yaml --model voxtral
uv run --extra moulsot darija transcribe -c configs/gold.yaml --model moulsot
darija agree       -c configs/gold.yaml
darija merge       -c configs/gold.yaml
darija labels      -c configs/gold.yaml
darija gold-export -c configs/gold.yaml                     # writes resources/gold_ids.txt
#    -> open work/gold/gold/gold.csv, listen, fix gold_text, put x in `checked`
darija eval        -c configs/gold.yaml

# 2. Calibration (iteration 1)
darija prepare    -c configs/calib.yaml
darija transcribe -c configs/calib.yaml --model cohere
darija transcribe -c configs/calib.yaml --model voxtral
darija agree      -c configs/calib.yaml       # pairwise CER between sources
darija merge      -c configs/calib.yaml --mode batch-submit
darija merge      -c configs/calib.yaml --mode batch-collect   # rerun until all collected
darija labels     -c configs/calib.yaml

# 3. extra-gt-2.5 (iteration 2): same commands with configs/extra_v1.yaml

# 4. Training data
darija build-train -c configs/calib.yaml -c configs/extra_v1.yaml --out your-username/darija-train --push
```

Notes:
- Any config value can be overridden on the command line: `--set select.n=30 --set select.duration=[2,20]`.
- Selection (`select:`): `n` clips and/or `hours` of audio, `duration` range in seconds (default 3-15,
  measured on the audio itself), `pesq_min`, `max_per_channel`. Clips are taken row group by row group,
  round-robin across channels, so a run covers as many channels as possible.
- Every stage is resumable. `transcribe` skips finished ids. Split a run across sessions
  with `--shard i --num-shards n`. On a fresh VM, `darija pull -c <config>` restores the run.
- `merge --mode sync` gives fast feedback on small runs. Batch mode costs 50% less and
  finishes within about an hour.
- `darija eval --hyp qwen=preds.parquet` scores any other model (e.g. your fine-tuned
  Qwen3-ASR) on the same gold set.
- The judge needs `ANTHROPIC_API_KEY`. Model and effort are in `merge:` in the config.

## Voxtral with vLLM

The transformers backend runs Voxtral Realtime at about 1.4-2.3x real time on a T4. vLLM
batches every open clip together and replays each decoder step as a CUDA graph. The vLLM
server lives in its own environment, so it never fights the project's transformers pin;
the project only talks to it over a websocket.

```bash
# once per Colab VM: a separate environment for the server
uv venv /content/vllm-env --python 3.12
uv pip install --python /content/vllm-env/bin/python -U vllm --torch-backend=auto "mistral-common[audio]>=1.9.0" "transformers>=5"

# start it in the background (T4: fp16, no bf16), then wait for "Application startup complete"
VLLM_DISABLE_COMPILE_CACHE=1 nohup /content/vllm-env/bin/vllm serve mistralai/Voxtral-Mini-4B-Realtime-Arabic --tokenizer-mode mistral --dtype half --max-model-len 1024 --gpu-memory-utilization 0.92 --compilation_config '{"cudagraph_mode": "PIECEWISE"}' > vllm.log 2>&1 &
while ! grep -q "Application startup complete" vllm.log; do pgrep -f "vllm serve" >/dev/null || { echo "server died"; tail -40 vllm.log; exit 1; }; sleep 10; done && echo ready

# use it: same model name, same output folder, other backend (plain `uv run`, no extra needed)
V="--set asr.models.voxtral.backend=vllm --set asr.models.voxtral.batch_size=64"
darija smoke      $P --model voxtral -n 16 $V
darija transcribe $P --model voxtral $V
```

- If startup fails while compiling, replace the `--compilation_config ...` line with `--enforce-eager`
  (no CUDA graphs, still continuous batching).
- Only one model fits on a T4: stop the server (`pkill -f "vllm serve"`) before running Cohere or MoulSot.
- `--max-model-len 1024` covers a 15 s clip (one step per 80 ms of audio, plus the prompt). On a T4 the
  weights leave ~3.4 GB of KV cache, about 1 MB per step, so a much longer limit fails at startup.
- `concurrency` (default 12) is how many clips are in flight; a T4's KV cache holds about a dozen clips.
  vLLM queues anything beyond that.

### MoulSot (and Cohere) with vLLM

vLLM serves Qwen3-ASR models, MoulSot included, on its OpenAI-style `/v1/audio/transcriptions`
route. Same server environment as above; only one model fits on a T4 at a time.

```bash
pkill -f "vllm serve"
# the Hub repo ships one model.safetensors plus a stale 2-shard index that vLLM trusts: drop the index
/content/vllm-env/bin/python -c "from huggingface_hub import snapshot_download; snapshot_download('atlasia/moulsot.v0.3', local_dir='/content/moulsot', ignore_patterns=['*.pth', 'trainer_state.json'])"
rm -f /content/moulsot/model.safetensors.index.json
nohup /content/vllm-env/bin/vllm serve /content/moulsot --served-model-name atlasia/moulsot.v0.3 --dtype half --max-model-len 2048 --gpu-memory-utilization 0.9 > vllm.log 2>&1 &
while ! grep -q "Application startup complete" vllm.log; do pgrep -f "vllm serve" >/dev/null || { echo "server died"; tail -40 vllm.log; break; }; sleep 10; done; grep -q "Application startup complete" vllm.log && echo ready

M="--set asr.models.moulsot.backend=vllm --set asr.models.moulsot.batch_size=128"
darija smoke      $P --model moulsot -n 30 $M
darija transcribe $P --model moulsot $M
```

Cohere the same way (gated model: `HF_TOKEN` must be set in the shell that starts the server):

```bash
pkill -f "vllm serve"
# fp16 crashes ("expected scalar type Float but found Half"): use float32 on a T4, bfloat16 on newer GPUs.
# On a T4 this gives 14.3x, slower than the transformers backend (20.6x), so keep transformers there.
nohup /content/vllm-env/bin/vllm serve CohereLabs/cohere-transcribe-arabic-07-2026 --dtype float32 --gpu-memory-utilization 0.9 > vllm.log 2>&1 &
C="--set asr.models.cohere.backend=vllm --set asr.models.cohere.batch_size=128"
darija smoke $P --model cohere -n 30 $C
```

## Design choices

- **Normalization is for scoring only** (`normalize.py`). It removes alef/hamza, ة/ه, ى/ي,
  tashkeel, punctuation and digit-form differences, so agreement and WER/CER don't count
  spelling variants as errors. Training text comes from the LLM, following
  `resources/style_guide.md`.
- **The style guide is a draft.** Edit it before the large runs, because it becomes the
  dataset's spelling convention. An optional reference lexicon (e.g. built from DODa) can
  be added with `merge.lexicon`.
- **The judge can only choose, not invent.** It may respell a word, but cannot add words
  no candidate has. It can reject a clip. Candidates are shuffled and anonymized by default.
- **Every clip goes to the judge** (`merge.mode: all`), so every label follows one
  spelling convention, and the judge, not a CER threshold, decides what to reject.
  Agreement between sources can't prove a transcript right, and with only two voters a
  single hallucination would drop a good clip. `agree` still runs: its scores (`max_cer`,
  `mean_cer`, pairwise `cer_*`/`wer_*`) are kept as columns in `labels.parquet` for
  filtering training data later. `merge.mode: disagreements` brings back the cheaper
  accept/drop routing (`accept_cer`, `drop_cer`).
- **Gold first.** Gold clips come from the test split, so they are fair to every model
  including MoulSot.0.3. `resources/gold_ids.txt` excludes them from every other run and
  from training data.
